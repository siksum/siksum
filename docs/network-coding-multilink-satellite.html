위성 간 통신을 위한 네트워크 코딩 기반 다중 링크 전송

데이터 두 개와 둘을 섞은 복구용 패킷을 여러 링크로 나눠 보냈습니다. 잡음이나 공격으로 링크 하나가 끊겨도 남은 패킷으로 원본을 복구하는지 확인했습니다.

역할
공저자
게재
ASK 2025, 한국정보처리학회, Vol. 32, No. 1, pp. 85–87, 2025.05.31
복구 실패율(RFR, 끊긴 데이터를 되살리지 못한 비율)
65.9% → 32.0%

DoS로 링크 하나를 제거한 시뮬레이션, Conv1 대비. 차이는 33.9%p

비트 오류율(BER, 수신 비트 중 틀린 비율)
23.5% → 9.08%

같은 조건

데이터 10Kbit 전송 지연
0.1초

Conv1 0.07초, Conv2 약 0.18초

제안 배경선행 연구해결책입증기여와 다음 단계

제안 배경

내용

위성 통신은 손실과 지연이 커서 링크 하나가 공격받아도 서비스가 멈출 수 있습니다.

통신 환경
전파 거리가 길고 주파수가 제한돼 지상 통신보다 손실과 지연이 큽니다.
실제 사례
2022년 KA-SAT 위성 사례에서는 우크라이나와 유럽에서 통신이 광범위하게 중단됐습니다.

선행 연구

내용

반복 전송은 주파수를 낭비하고 기존 복구 방식은 링크가 하나인 경우만 다뤘습니다.

반복 송신
같은 데이터를 반복해 보내는 방식은 자원이 한정된 위성 환경에서 주파수를 낭비합니다.
여분 패킷
여분 패킷으로 손실을 복구하는 방식은 단일 링크만 가정했습니다.

해결책

내용

데이터 두 개와 둘을 섞은 복구용 패킷 하나를 세 링크에 나눠 보냅니다.

전송 방식
세 링크에 데이터 A, B와 둘을 비트 단위로 섞은 복구용 패킷을 하나씩 싣습니다.
복구 방법
A가 사라져도 지상국은 B와 복구용 패킷으로 A를 계산해 되살립니다.

입증

내용

시뮬레이션에서 링크 하나가 끊겼을 때 복구 실패율이 65.9%에서 32.0%로 줄었습니다.

실험 설정
Python 시뮬레이션으로 나눠 보내는 방식, 세 번 반복해 보내는 방식과 비교했습니다.
결과
비트 오류율은 23.5%에서 9.08%로 낮아졌고 10Kbit 전송 지연은 0.1초로 두 방식의 중간이었습니다.
한계
실제 위성 링크 실험은 없고 공격도 링크 하나 제거로 단순하게 모델링했습니다.

기여와 다음 단계

기여

중복 전송보다 지연을 줄이면서 링크 손실 때 복구가 가능함을 시뮬레이션으로 보였습니다.

참여
공저자로 참여했습니다.
논문의 기여
데이터를 섞어 보내는 네트워크 코딩을 위성 다중 링크 전송에 적용했습니다.

후속 연구

시뮬레이션에 머문 결과를 테스트베드에서 확인하는 일이 남았습니다.

현재 한계
실제 위성 링크나 테스트베드 실험은 없습니다.
향후 계획
테스트베드를 구축해 다양한 조건에서 성능을 평가할 계획입니다.
