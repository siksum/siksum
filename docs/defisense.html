DeFiSense

여러 프로토콜을 거친 거래를 연결해 공격 과정과 자금 이동, 손익의 원인을 복원합니다.

상태
Ongoing Research
개요문제와 목표검토와 선택구현과 난관검증 결과기여와 다음 단계이 경험이 만든 판단 기준

프로젝트 개요

  • 공격 거래 하나에서 공격 주체, 피해자와 피해액, 손익, 왜곡된 값이 사용된 지점, 행동 순서를 하나의 의미 증거 그래프로 복원하는 연구입니다.
  • 현재는 돈이 어디로 이동했는지를 넘어, 공격자가 바꾼 값만 거래 전 상태로 되돌려 재실행했을 때 지급이 얼마나 줄어드는지 측정해 ‘조작 때문에 생긴 손실’을 확인하는 방법을 구현하고 있습니다.

문제와 목표

해결해야 한 문제

기존 사고 분석은 자금 이동이나 공격 단계는 보여주지만, 담보 대출형 공격처럼 겉으로는 정상 대출과 비슷한 거래에서 누가 피해자이고 어떤 왜곡값이 지급 판단에 쓰였는지를 계산으로 연결하기 어렵습니다.

왜 이 문제였나

사고 대응에서는 공격 이름보다 누가 무엇을 잃었고 어떤 의사결정 값이 잘못 사용됐는지가 우선입니다. 이 연결이 없으면 손실 산정, 원인 계약 확인과 후속 통제가 서로 다른 수작업으로 남습니다.

목표

지금은 소스코드, 주소 라벨과 LLM에 의존하지 않고 단일 공격 거래의 다섯 요소를 복원하는 데 집중합니다. 피해와 왜곡값 사용의 인과 관계도 실행 결과로 검산하려고 합니다.

검토와 선택

검토한 방법

초기에는 이벤트 로그만으로 DeFi 행위를 분류하고 규칙과 LLM으로 PMA를 판정했습니다. 이후 전체 명령어 값 흐름, 의미 그래프, 보고서 보조, sink 중심 추적과 원인 카드 생성 등 여러 경로를 비교했습니다.

전체 명령어 기록은 219건에서 약 11.3GB와 1.2GB 메모리를 사용하면서도 목표 정확도를 만들지 못해 중단했습니다. 원인 설명을 먼저 생성하는 방식도 정답을 알고 설명하는 누출 위험 때문에 핵심 방법에서 제외했습니다.

선택한 방법

싼 증거부터 사용하는 계층형 절차를 선택했습니다. 거래 / 호출 / 전송으로 주체와 행동 / 손익을 만들고, 공격자가 쓴 저장값을 뒤 호출이 읽은 후보만 좁힌 뒤 그 값만 되돌리는 반사실 재실행으로 피해자와 왜곡값 사용 지점을 함께 확인합니다.

구현과 난관

기술 스택

  • TypeScript / Node.js / tsx
  • EthereumJS VM / EVM / StateManager / Block / Tx
  • JSONL typed claims / EVM trace / event log / state diff
  • Z3 solver / reproducible fixtures / Node test runner

구현

원본 거래 재실행과 영수증 / 로그 일치 검사, 호출 프레임과 저장값 read/write 추적, 토큰 / 네이티브 자산 손익, 공격 주체 / 수혜자 / 손실 부담자 / 행동 요약을 각각 독립 산출물로 만들었습니다.

현재는 후보 저장값을 거래 전 값으로 읽히게 한 재실행 결과를 원본과 비교하고, 조작과 연결된 지급 감소량과 피해자 그룹을 그래프와 보고서에 연결하는 producer를 일반화하고 있습니다.

어려움

원시 전송 합계는 직접 지급자를 찾을 수 있어도 발행 / 소각, 부채, 담보, 지분 토큰과 프로토콜 내부 상태를 같은 손익으로 해석하기 어렵습니다. 무엇을 원인으로 볼지 사람이 이미 아는 사고 설명이 구현에 섞이면 평가가 오염될 위험도 있었습니다.

해결

자산 / 부채 / 담보 / 지분을 분리한 원장을 두고, 증거가 부족하면 억지로 채우지 않는 경계를 만들었습니다. 개발 사례의 정답을 typed claim으로 먼저 동결하고, producer가 읽을 수 없는 별도 정답 파일과 단계별 검증기로 누출을 차단했습니다.

검증 결과

정량 결과

15개 개발 사례를 1,031개 typed claim으로 바꾸고 정답 형식과 추출 기준 검증을 15/15 통과했습니다. 다만 현재 raw-only 기준선은 다섯 요소를 모두 맞춘 사례가 0/15이고, 219개 원시 입력 처리도 의미 행동과 원인까지 완성한 성능 결과는 아닙니다.

목표 달성

역할 / 손익 / 그래프 / 보고서의 부분 파이프라인과 검증 계약은 마련했습니다. 반사실 재실행 producer의 일반화와 정상 / 경계 사례를 포함한 동결 평가는 진행 중이므로, 탐지 성능 우월성이나 운영 적용 완료를 주장하지 않습니다.

기여와 다음 단계

기여

그래프 자체가 아니라, 추론한 행동을 자산 / 부채 / 상태 변화와 교차검증하고 증거가 부족할 때 보류하며, 왜곡된 값과 손실을 반사실 실행으로 연결하는 방법을 연구 기여로 좁혔습니다.

배운 점

많은 거래를 처리했다는 수치보다 각 결론이 어느 증거에서 나왔는지와 틀렸을 때 어느 단계에서 깨졌는지가 더 중요했습니다. 금융 행위는 전송량 하나가 아니라 자산 / 부채 / 담보 / 지분의 관계로 설명해야 했습니다.

한계

현재 범위는 한 거래 안에서 끝나는 EVM 계열 공격입니다. 여러 거래에 걸친 공격, 외부 시장 가격의 장기 변화와 Arbitrum 전 범위는 후순위이며, 개발 사례의 성공을 평가 집합 성능으로 일반화할 수 없습니다.

후속 연구

반사실 effect/action producer와 전체 경계 원장을 완성한 뒤 15개 사례와 정상 / 경계 fixture를 다시 검증합니다. 이후 동결한 개발 / 평가 분할에서 피해자, 피해액, 왜곡값 사용 지점, 사건당 비용을 측정할 계획입니다.

이 경험이 만든 판단 기준

조직에서 내리는 판단

온체인 사고를 거래 목록이 아니라 거래 주체, 자산 / 부채 변화, 손실 부담자, 잘못 사용된 의사결정 값으로 정리하는 접근입니다. 사고 조사, 손실 산정과 재발 방지 통제를 같은 증거 묶음으로 연결할 가능성을 검증하고 있으며, 현재는 연구 단계입니다.
