DeFiSense

공개 거래 기록만으로 DeFi 가격 조작 공격을 탐지하고, 누가 이익을 얻고 손실을 부담했는지 복원합니다.

상태
석사 학위논문 완료(2026.08), 확장 연구 진행 중

개요

공개 거래 기록만으로 가격 조작 공격을 탐지하는 프레임워크를 구현했습니다.

역할

석사 학위논문으로 문제 정의, 데이터셋 구축, 구현과 평가를 단독으로 수행했습니다.

성과

공격 220건과 정상 거래 131건에서 공격 탐지율 93.2%, 정상 거래 판정률 100%였습니다.

문제

내용

가격 조작 사고가 나도 공개 기록만으로는 누가 손실을 부담했는지 알기 어렵습니다.

공격 방식
탈중앙 금융(DeFi)은 담보 가치를 자동 계산하므로 가격을 왜곡하면 의도보다 많은 자산이 빠져나갑니다.
기존 방식
소스코드와 내부 호출 기록이 필요해 코드가 비공개인 서비스의 사고에는 쓰기 어려웠습니다.

접근

내용

공개 거래의 이벤트 로그와 토큰 전송만으로 공격을 판정하는 프레임워크를 구현했습니다.

행동 복원
개별 전송을 예치와 교환, 차입과 상환 같은 금융 행동으로 묶어 그래프로 연결했습니다.
판정
규칙으로 먼저 판정하고 판단이 어려운 거래에만 LLM을 병용했습니다.
역할
석사 학위논문으로 문제 정의, 데이터셋 구축, 구현과 평가를 단독으로 수행했습니다.

결과

내용

완료한 석사논문에서 공격 탐지율 93.2%, 정상 거래 판정률 100%를 확인했습니다.

탐지(완료)
공격 220건 중 205건을 탐지했고 정상 거래 131건은 모두 정상으로 판정했습니다.
비용(완료)
모든 거래에 LLM을 적용한 방식과 비교해 LLM 호출 수가 58% 감소했습니다.
확장 연구
여러 거래에 걸친 자금 흐름과 최종 손익을 복원하는 연구는 진행 중이며 성능 결과가 아직 없습니다.

한계와 다음

내용

한 거래 안에서 끝나는 공격만 다루며 운영 환경에 적용한 결과는 아닙니다.

범위
여러 거래에 걸친 공격과 외부 시장 가격의 장기 변화는 아직 다루지 않습니다.
다음
왜곡된 값을 되돌려 거래를 다시 실행하는 모듈을 완성한 뒤 피해자와 피해액을 측정할 계획입니다.

실무 활용

내용

블록체인 서비스에서 사고가 났을 때 원인과 손실을 설명하는 데 쓸 수 있습니다.

활용 장면
어떤 거래가 잘못된 지급을 만들었고 누가 손실을 부담했는지 확인해야 할 때입니다.
활용 방법
공개 거래 기록만으로 공격 과정과 자금 흐름을 복원해 근거와 함께 보고합니다.
주의할 점
확장 연구는 진행 중이며 운영 환경에 적용한 결과는 아닙니다.
작업 기록 전체 보기
기술 스택
TypeScript / Node.js / tsx / EthereumJS VM / EVM / StateManager / Block / Tx / JSONL typed claims / EVM trace / event log / state diff / Z3 solver / reproducible fixtures / Node test runner
해결해야 한 문제
기존 사고 분석은 피해자와 왜곡된 값을 계산으로 연결하기 어렵습니다. 자금 이동이나 공격 단계는 보여줍니다. 담보 대출형 공격은 겉으로는 정상 대출과 비슷합니다. 이런 거래에서 누가 피해자이고 어떤 왜곡값이 지급 판단에 쓰였는지를 계산으로 연결하기 어렵습니다.
왜 이 문제였나
사고 대응에서는 공격 이름보다 누가 무엇을 잃었는지가 우선입니다. 누가 무엇을 잃었고 어떤 의사결정 값이 잘못 사용됐는지가 공격 이름보다 우선입니다. 손실 산정, 원인 계약 확인과 후속 통제가 서로 다른 수작업으로 남습니다.
목표
확장 연구의 목표는 단일 공격 거래의 다섯 요소를 복원하는 것입니다. 지금은 소스코드, 주소 라벨과 LLM에 의존하지 않고 단일 공격 거래의 다섯 요소를 복원하는 데 집중합니다. 피해와 왜곡값 사용의 인과 관계도 실행 결과로 검산하려고 합니다.
검토한 방법
학위논문의 방법에서 출발해 여러 경로를 비교했고, 두 가지는 중단하거나 제외했습니다. 이벤트 로그만으로 DeFi 행위를 분류하고 규칙과 LLM으로 가격 조작 공격을 판정했습니다. 이후 전체 명령어 값 흐름, 의미 그래프, 보고서 보조, sink 중심 추적과 원인 카드 생성 등 여러 경로를 비교했습니다. 전체 명령어 기록은 219건에서 약 11.3GB와 1.2GB 메모리를 사용하면서도 목표 정확도를 만들지 못해 중단했습니다. 원인 설명을 먼저 생성하는 방식은 정답을 알고 설명하는 누출 위험 때문에 핵심 방법에서 제외했습니다.
선택한 방법
싼 증거부터 사용하는 계층형 절차를 선택했습니다. 거래와 호출, 전송으로 주체와 행동, 손익을 만듭니다. 공격자가 쓴 저장값을 뒤 호출이 읽은 후보만 좁힙니다. 그 값만 되돌려 거래를 다시 실행하는 반사실 재실행으로 피해자와 왜곡값 사용 지점을 함께 확인합니다.
구현
확장 연구에서 단계별 결과를 독립 산출물로 만들었고, 재실행 비교는 일반화하는 중입니다. 원본 거래 재실행과 영수증 및 로그 일치 검사, 호출 프레임과 저장값 읽기와 쓰기 추적을 각각 독립 산출물로 만들었습니다. 토큰과 네이티브 자산 손익, 공격 주체와 수혜자, 손실 부담자와 행동 요약도 독립 산출물로 만들었습니다. 후보 저장값을 거래 전 값으로 읽히게 한 재실행 결과를 원본과 비교합니다. 조작과 연결된 지급 감소량과 피해자 그룹을 그래프와 보고서에 연결하는 모듈(producer)을 일반화하고 있습니다.
어려움
전송 합계만으로는 손익을 해석하기 어려웠고 평가가 오염될 위험도 있었습니다. 원시 전송 합계는 직접 지급자를 찾을 수 있어도 발행과 소각, 부채, 담보, 지분 토큰과 프로토콜 내부 상태를 같은 손익으로 해석하기 어렵습니다. 무엇을 원인으로 볼지 사람이 이미 아는 사고 설명이 구현에 섞이면 평가가 오염될 위험이 있었습니다.
해결
원장을 나누고 정답을 먼저 동결해 누출을 차단했습니다. 자산, 부채, 담보, 지분을 분리한 원장을 두고, 증거가 부족하면 억지로 채우지 않는 경계를 만들었습니다. 개발 사례의 정답을 형식이 정해진 주장(typed claim)으로 먼저 동결했습니다. 결과를 만드는 모듈(producer)이 읽을 수 없는 별도 정답 파일과 단계별 검증기로 누출을 차단했습니다.
정량 결과
앞의 세 항목은 완료한 학위논문 평가이고, 확장 연구는 아직 성능 결과가 없습니다. 351건 가운데 공격 220건 중 205건을 탐지했고 정상 131건의 오탐은 0건이었습니다(재현율 93.2%, 정밀도 100%, F1 96.5%). 놓친 15건 중 10건은 전송 시 보상이 분배되는 소형 토큰 유형이었습니다. 규칙만 쓰면 재현율 89.5%이고, LLM은 351건 중 147건(42%)에만 호출했습니다. 모든 거래에 LLM을 쓰는 구성과 비교하면 건당 시간은 약 80초에서 34초, 비용은 약 $0.150에서 $0.063이었습니다. 같은 220건에서 DeFiRanger는 56.8%, DeFiScope는 62.3%를 탐지했습니다. 15개 개발 사례를 1,031개 typed claim으로 바꾸고 정답 형식과 추출 기준 검증을 15/15 통과했습니다. 다만 현재 raw-only 기준선은 다섯 요소를 모두 맞춘 사례가 0/15이고, 219개 원시 입력 처리도 의미 행동과 원인까지 완성한 성능 결과는 아닙니다.
목표 달성
학위논문의 탐지 목표는 달성했고, 확장 연구는 진행 중입니다. 탐지 목표는 달성했습니다. 역할, 손익, 그래프, 보고서의 부분 파이프라인과 검증 계약은 마련했습니다. 반사실 재실행 producer의 일반화와 정상 및 경계 사례를 포함한 동결 평가는 진행 중입니다. 확장 연구에서는 탐지 성능 우월성이나 운영 적용 완료를 주장하지 않습니다.
기여
연구 기여를 그래프 자체보다 교차검증과 반사실 실행으로 좁혔습니다. 추론한 행동을 자산과 부채, 상태 변화와 교차검증하고 증거가 부족할 때 보류합니다. 왜곡된 값과 손실을 반사실 실행으로 연결하는 방법을 연구 기여로 좁혔습니다.
배운 점
처리한 거래 수보다 각 결론의 증거가 더 중요했습니다. 많은 거래를 처리했다는 수치보다 각 결론이 어느 증거에서 나왔는지와 틀렸을 때 어느 단계에서 깨졌는지가 더 중요했습니다. 전송량 하나로는 설명할 수 없었고 자산, 부채, 담보, 지분의 관계로 설명해야 했습니다.
한계
현재 범위는 한 거래 안에서 끝나는 EVM 계열 공격입니다. 여러 거래에 걸친 공격, 외부 시장 가격의 장기 변화와 Arbitrum 전 범위는 후순위입니다. 개발 사례의 성공을 평가 집합 성능으로 일반화할 수 없습니다.
후속 연구
남은 모듈을 완성해 다시 검증한 뒤 동결한 평가 집합에서 측정할 계획입니다. 반사실 effect/action producer와 전체 경계 원장을 완성한 뒤 15개 사례와 정상 및 경계 fixture를 다시 검증합니다. 이후 동결한 개발과 평가 분할에서 피해자, 피해액, 왜곡값 사용 지점, 사건당 비용을 측정할 계획입니다.
조직에서 내리는 판단
금융회사의 블록체인 도입은 코드 검증만으로 끝나지 않는다는 점을 배웠습니다. 운영 중 사고가 발생하면 어떤 거래가 잘못된 자금 지급을 만들었고 그 손실을 누가 부담했는지 설명할 수 있어야 합니다. 공개 거래 기록만으로 공격 과정과 자금 흐름을 복원하면서 탐지 결과를 실제 손실 원인과 연결하는 것이 중요하다고 느꼈습니다. 현재 확장 연구는 진행 중이며 운영 환경에 적용한 결과는 아닙니다.
