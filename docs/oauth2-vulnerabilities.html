OAuth 2.0의 보안 취약점 분석 및 보안 대책 연구

소셜 로그인에 쓰이는 OAuth 2.0의 인증 흐름을 직접 점검했습니다. 클라우드에서 접근 토큰 탈취가 관리자 계정과 데이터 침해로 번지는 시나리오와 대책을 정리했습니다.

역할
공저자
게재
CISC-S'22, 한국정보보호학회, 2022
제안 배경선행 연구해결책입증기여와 다음 단계

제안 배경

내용

소셜 로그인 토큰 하나가 탈취되면 피해가 여러 서비스와 클라우드로 번집니다.

동작 방식
OAuth 2.0은 한 번의 인증으로 다른 서비스의 접근 권한까지 부여합니다.
실제 사례
2022년 4월 GitHub에서 탈취된 토큰으로 여러 조직의 데이터가 무단 다운로드됐습니다.

선행 연구

내용

기존 연구에는 최근 피해 양상을 반영한 공격 시나리오가 부족했습니다.

기존 연구
OAuth 1.0과 2.0을 비교한 분석과 통합 로그인의 보안성을 다룬 연구가 있습니다.
남은 공백
이전에 발생한 위협을 주로 다뤘습니다.

해결책

내용

클라우드 환경의 토큰 탈취 시나리오를 작성하고 취약점 두 가지에 대책을 제시했습니다.

위험 시나리오
상위 관리자의 접근 토큰이 탈취되면 그 관리자가 맡은 모든 사용자의 클라우드가 노출됩니다.
대책
로그인 뒤 돌아갈 주소는 완전 일치로 검증하고 서비스 비밀값 확인은 의무화하도록 제시했습니다.

입증

내용

직접 만든 로그인 사이트에서 인가 코드를 가로채 토큰을 받았고 정량 지표는 없습니다.

실험 설정
네이버와 카카오 로그인을 연동한 사이트를 만들고 오가는 패킷을 분석했습니다.
결과
응답 패킷에서 인가 코드를 가로채 접근 토큰과 갱신 토큰이 담긴 응답을 받았습니다.
한계
인가 코드가 일회용이어서 공격자가 먼저 쓰면 정상 사용자의 로그인이 실패합니다.

기여와 다음 단계

기여

클라우드 환경의 토큰 탈취 시나리오와 국내 주요 사업자의 설정 현황을 정리했습니다.

참여
공저자로 참여했습니다.
논문의 기여
카카오, 구글, 네이버의 대책 적용 현황을 실습으로 확인했습니다.

후속 연구

수작업으로 한 점검을 전용 도구로 자동화하는 것이 다음 계획입니다.

현재 방식
이번 연구에서는 패킷을 직접 분석해 점검했습니다.
향후 계획
OAuth 2.0 전용 침투 테스트 도구를 개발해 점검을 자동화할 계획입니다.
