Retrieval-Augmented Chain-of-Thought 프레임워크를 활용한 DeFi 스마트 컨트랙트 취약점 탐지

과거 해킹 사례 585건을 근거로 찾아 주고, LLM이 취약점 유형과 문제가 된 함수까지 짚도록 만든 탐지 방법입니다.

제안 배경

내용

DeFi 취약점은 함수 간 실행 순서와 외부 연결에서 나타나 판단하기 어렵습니다.

상황
여러 컨트랙트가 연결돼 거래를 처리하며 2024년 해킹 피해는 약 20억 달러였습니다.
필요
코드와 거래 흐름, 경제적 맥락을 함께 참조하는 탐지 방법이 필요했습니다.

선행 연구

내용

정적 분석은 복잡한 흐름을 복원하지 못했고, LLM은 판단 근거가 불분명했습니다.

정적 분석
복잡한 DeFi 로직에서는 오탐과 미탐이 생깁니다.
LLM 단독
사전 지식에만 의존해 판단 근거가 불분명하고 결과가 달라질 수 있었습니다.

해결책

내용

실제 해킹 사례를 근거로 주고 현재 코드와 순서대로 비교한 뒤 결과를 다시 검증합니다.

사례 DB
해킹과 취약 사례 585건에 공격 원인과 취약 함수를 연결했습니다.
검증
1차 분석 뒤 경제적 조건과 실행 순서를 다시 확인해 최종 결과를 정합니다.

입증

내용

취약점 유형과 취약 함수를 각각 60% 정확도로 찾아 비교 대상보다 높았습니다.

실험 설정
취약점 유형과 문제가 된 함수를 얼마나 정확히 찾는지 평가했습니다.
결과
선행 연구는 유형 46%와 함수 15%였고 지연 시간은 28%, 비용은 38% 줄었습니다.
한계
수학적 오류 유형은 50%였고 비용은 LLM 단독 방식보다 높았습니다.

기여와 다음 단계

기여

취약 여부만이 아니라 수정이 필요한 함수까지 찾는지를 따로 측정했습니다.

역할
제1저자로 연구를 수행하고 학회에서 발표했습니다.
배운 점
원인을 좁혀 실제 수정으로 이어질 정보를 남기는 것이 중요하다는 점을 배웠습니다.

후속 연구

수학적 연산 취약점의 정확도를 높이는 것이 남은 과제입니다.

한계
수학적 연산 취약점의 정확도가 50%에 머뭅니다.
향후 과제
정적 분석과 통합하고 탐지 결과를 운영에 연계하는 것입니다.

실무 활용

내용

AI 분석 도구를 도입할 때 결과를 어디까지 믿을 수 있는지 평가하는 데 쓸 수 있습니다.

활용 장면
AI가 취약하다고 판정했지만 근거와 수정 위치가 불분명할 때입니다.
활용 방법
과거 사고와 코드 위치를 근거로 요구하고, 자동화할 부분과 사람이 다시 확인할 부분을 나눕니다.
