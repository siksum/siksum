A Fault-Tolerant Consensus Mechanism for Scalable and Reliable Blockchain Systems

초기 고장과 마모 고장처럼 장비에서 자연스럽게 생기는 장애를 신뢰도 모델로 예측했습니다. 신뢰도가 높은 소수의 노드만 합의에 참여시키고 100노드 환경에서 기존 PBFT와 지연시간을 비교했습니다.

역할
제1저자, 발표
게재
2025 IEEE ICCT-Pacific, Matsue, Shimane, Japan, 2025
실험 규모
100노드, 1,000블록, 100회 반복

욕조 곡선 신뢰도 모델, Python 시뮬레이터

합의 메시지 복잡도
2(n-f)² → 2(c-b)²

n 전체 노드, f 결함 허용 수, c 위원회 크기(c < n), b 고장 노드 수

제안 배경선행 연구해결책입증기여와 다음 단계

제안 배경

내용

노드가 늘수록 느려지는 PBFT에서 장비의 자연 고장을 다루는 방법을 연구했습니다.

문제
PBFT는 노드가 늘면 통신량이 제곱으로 늘어 대규모 환경에서 느려집니다.
연구 범위
장비 초기 불량이나 노후 같은 자연 고장만 다뤘고 악의적 행동은 제외했습니다.

선행 연구

내용

기존 개선안에서는 점수가 떨어진 노드가 회복돼도 합의에서 계속 배제됐습니다.

리더와 다층
권한이 몰린 리더나 상위 노드의 고장이 전체에 영향을 줍니다.
점수 기반
일시적 문제로 점수가 떨어진 노드는 회복돼도 계속 배제됩니다.

해결책

내용

합의 참여 기록으로 노드 순위를 매기고, 상위 노드만으로 합의 그룹을 구성합니다.

상태 기록
합의 메시지의 성공과 실패를 기록하고 이웃과 합산해 순위를 매깁니다.
복귀
합의가 실패하면 갱신된 순위로 그룹을 다시 짜므로 점수가 낮아진 노드도 복귀합니다.

입증

내용

고장이 많은 구간에서도 rPBFT의 지연시간은 0.2~0.3초 수준을 유지했습니다.

실험 설정
Python 시뮬레이터로 100노드가 1,000블록을 생성하는 실험을 100회 반복했습니다.
결과
기존 PBFT는 고장이 많은 구간에서 지연이 크게 올랐고 rPBFT는 0.2~0.3초였습니다.
한계
지연시간만 비교했고 고장이 없는 환경에서는 기존 PBFT의 부담이 더 낮았습니다.

기여와 다음 단계

기여

WISA 2024 포스터의 rPBFT를 논문 형식으로 정리해 학회에서 발표했습니다.

역할
제1저자로 연구를 수행하고 학회에서 발표했습니다.
추가한 내용
관련 연구 분류와 메시지 복잡도 식을 담았습니다.

후속 연구

고장 없는 환경의 부담을 줄이는 것이 과제였고, 연구는 저널 논문으로 이어졌습니다.

향후 과제
합의 그룹 크기를 동적으로 조정해 고장 없는 환경의 부담을 줄이는 것입니다.
이어진 연구
저널 논문에서 1,000노드 규모와 악의적 노드 비율 실험을 추가했습니다.
