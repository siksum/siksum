함수별 위험도와 권한 검증 강도를 점수로 계산해 권한 검증이 빠졌거나 우회될 수 있는 함수를 찾습니다. 자금이나 관리 권한을 다루는 함수를 배포 전에 점검하는 절차입니다.

제안 배경

내용

자금을 옮기는 함수에 호출자 권한 확인이 빠지면 곧바로 자산 손실로 이어집니다.

상황
탈중앙 금융(DeFi)은 중개 기관 없이 프로그램이 대출과 예치, 자산 교환을 처리합니다.
어려운 이유
프로토콜마다 권한 관리 방식이 달라 한 가지 규칙으로 점검하기 어렵습니다.

선행 연구

내용

기존 도구는 권한 흐름에서 생기는 논리적 결함을 잘 찾지 못했습니다.

기존 도구
선행 조사에서 자동화 도구 5종은 실제 공격 127건 중 11건만 탐지했습니다.
접근 제어
함수 이름이나 키워드에 의존해 표준을 따르지 않은 권한 로직에 약했습니다.

해결책

내용

함수마다 위험도와 권한 검증 강도를 점수로 매겨 검증이 부족한 함수를 찾습니다.

점수 계산
자산 이동과 외부 호출로 위험도를 매기고 권한 검증이 약할수록 점수가 높아집니다.
임곗값
보고 기준은 프로토콜의 점수 분포에 맞춰 고위험 함수일수록 낮게 자동 조정합니다.

입증

내용

실제 해킹 사례 20건 중 19건을 탐지했고 평균 1.72초가 걸렸습니다.

실험 설정
2020~2024년 해킹 사례 20건의 피해 컨트랙트를 기존 도구 두 가지와 비교했습니다.
결과
제안 기법은 19건, 정적 분석 도구는 3건, 동적 분석 도구는 9건을 탐지했습니다.
한계
제안 기법도 20건 중 1건은 탐지하지 못했습니다.

기여와 다음 단계

기여

권한 검증을 점수로 판정하는 절차를 설계하고 실제 사고로 비교한 논문입니다.

참여
제가 지도하던 멘티의 연구에 공저자로 참여했습니다.
논문의 기여
상위 5개 대출 프로토콜의 공통 구조를 정리하고 접근 제어를 점수로 판정했습니다.

후속 연구

실행 중에 생기는 상호작용은 포착하지 못해 동적 분석과의 결합이 과제입니다.

한계
코드를 실행하지 않고 분석해 실행 중의 복합적인 상호작용은 포착하지 못합니다.
향후 과제
동적 분석과 결합하고 실서비스 운영 로그로 신뢰성을 높이는 것입니다.
