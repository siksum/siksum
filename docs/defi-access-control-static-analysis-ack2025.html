제안 배경

내용

권한 확인 없이 호출되는 함수가 탈중앙 금융(DeFi) 해킹 피해의 최대 원인입니다.

피해 규모
Xangle 집계로 2023년 DeFi 해킹 피해액의 65.1%를 차지했습니다.
필요성
컨트랙트는 배포하면 고치기 어려워 배포 전 점검이 필요합니다.

선행 연구

내용

기존 자동화 도구는 공격의 일부만 막는다고 보고됐습니다.

도구의 한계
Zhou 등은 자동화 도구가 프로토콜 수준의 취약점을 찾기 어렵다고 지적했습니다.
예방 비율
Chaliasos 등은 대표 도구들이 전체 공격의 8%만 예방한다고 보고했습니다.

해결책

내용

함수마다 같은 다섯 가지를 차례로 확인해 권한 검증이 부족한 곳을 찾습니다.

점검 5단계
외부 호출 가능 여부, 민감한 이름, 권한 제한 유무와 수준, 추가 검증을 차례로 봅니다.
위험도 판정
검증이 부족한 함수는 핵심 기능을 수행하는지 확인해 위험도를 매깁니다.

입증

내용

해킹 사례 20건 중 19건을 탐지했고 속도는 기존 도구 Slither보다 느렸습니다.

실험 설정
2020~2024년 해킹 사례 20건에 제안 방법과 기존 도구 두 개를 적용했습니다.
결과
제안 방법 19건, Echidna 9건, Slither 3건을 탐지했고 평균 지연은 2.12초였습니다.
한계
놓친 1건은 무제한 발행 취약점으로 정적 규칙만으로는 찾기 어려웠습니다.

기여와 다음 단계

기여

프로토콜마다 다른 접근 제어를 같은 기준으로 점검하는 절차를 제시했습니다.

참여
제가 지도하던 멘티의 연구에 공저자로 참여했습니다.
논문의 기여
같은 기준의 점검 절차를 실제 해킹 사례로 기존 도구와 비교했습니다.

후속 연구
